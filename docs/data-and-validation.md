관측일과 별개로 실제 발생 시각, 처음 확인 가능했던 시각(`available_at`), 세션, 출처, 잠정/확정, 수정 버전을 남긴다. 모델 입력은 평가 시각 이전에 사용 가능했던 자료로 제한한다. 시각이나 값이 없으면 **미확인**으로 남긴다. 데이터 이용과 재배포 권한은 별개다. 공개 저장소·화면으로 원자료를 배포하기 전에 [KRX 시장정보 이용정책](https://data.krx.co.kr/inc/datasale/Market%20Data%20Usage%20Polices_ko.pdf) 등 실제 소스의 조건을 확인한다.

## 과거 사례 검증

1. 분석 전에 급락, 저점 재시험, 회복, 실패, 관측 기간을 고정한다. 과거 금융위기·코로나·2022년 긴축/재고조정 등은 다른 유형으로 구분하고, 사후 최저점 앞 2~4주 분석은 당시 신호 판정과 별도로 한다.
2. 조건만 충족한 날과 촉발·확인까지 기다린 날을 비교한다. 반례, 미확인 및 관측 기간이 덜 찬 경우까지 보고하고, 희소 사건은 거래일 수가 아니라 독립 사례 수로 센다.
3. 보조지표끼리 겹치는지 확인하고, 조건 변경은 다른 기간에서 검증한다. SOXL 거래활동은 SOXX 같은 기초 방향 지표와 비교한 뒤 추가 설명력이 있는지 본다. 순유입이나 청산을 거래량에서 추정하지 않는다.
4. 성과 지표는 **추가 낙폭**, **확인을 기다린 비용**, **정해진 기간의 종가 수익률**을 분리한다. 다음 정규장 시가는 관측 기준일 뿐 실체결이 아니다. 조건군과 확인군의 비교 시작일·종료일이 달라질 수 있으며, 확인된 사례만 따로 비교하면 선택 편향이 생긴다.

## 구현 현황과 다음 작업

- **구현:** [research](../research)의 규칙 기반 백테스트와 [database](../database)의 범용 읽기 전용 입력 규격. 합성 데이터로 테스트하며 실제 시장에서 규칙의 유효성을 검증한 것은 아니다.
- **미구현:** 실데이터 자동 수집, 기존 운영 DB 연동, 채점 모델 배포, 웹 API·화면, 주문 처리.
- **다음:** 출처별 소규모 샘플로 거래일·게시 시각·누락을 검증 → 비공개 정규화 스냅샷에 적재 → 성공/실패가 모두 있는 과거 구간으로 리플레이. 입력·재현이 안정된 뒤 API와 화면을 붙인다.
